# StockPilot AI
## Product Requirements Document (PRD)

**Project Type:** AI-powered stock analysis and investment decision-support application  
**Version:** 1.0  
**Status:** Development Planning  
**Target Market:** Indian stock market (NSE and selected BSE-listed stocks)  
**Project Complexity:** Medium  
**Primary Goal:** Build a polished, practical, tool-using AI agent application using Agno, Python, and Streamlit.

---

# 1. Project Overview

## 1.1 Product Description

StockPilot AI is an AI-powered stock analysis and investment decision-support application that helps users explore potential stock investments based on their budget, investment duration, risk tolerance, and stock preferences.

Instead of simply returning a response generated by an LLM, StockPilot AI will use an agent built with the Agno framework to retrieve financial data, analyze historical stock performance, calculate technical indicators, retrieve relevant financial news, and explain its findings to the user.

For example, a user may enter:

"I have ₹10,000 to invest. I want to invest for three years and have moderate risk tolerance. Which Indian stocks should I consider?"

StockPilot AI will analyze relevant stock candidates, use real financial data where available, calculate useful metrics, and present a ranked shortlist with supporting evidence, risks, charts, and affordability calculations.

The application will also display the tools used during the analysis so users can understand how the agent arrived at its conclusions.

## 1.2 Problem Statement

Many beginner investors struggle to compare stocks because financial data is distributed across different platforms, metrics can be difficult to interpret, and generic AI responses may not be based on current market data.

StockPilot AI aims to make this process easier by combining financial data retrieval, Python-based calculations, web-based news discovery, and AI-generated explanations in one accessible interface.

## 1.3 Proposed Solution

Develop a Streamlit application that uses an Agno-powered AI agent to:

- Understand the user's investment preferences.
- Retrieve historical and current-available stock data.
- Calculate financial and technical indicators using Python.
- Retrieve relevant news and market information.
- Evaluate stocks against the user's selected preferences.
- Present transparent comparisons and evidence-based explanations.
- Show the tools executed during an analysis.
- Help users explore stocks without promising investment returns.

The project must achieve the following objectives:

1. Build a working AI agent using the Agno framework.
2. Integrate multiple actual Agno-compatible tools.
3. Use Yahoo Finance data through `YFinanceTools`.
4. Use `DuckDuckGoTools` to retrieve relevant web results and news.
5. Implement custom Python functions as callable agent tools.

## Feature 4: Custom Python Financial Tools

In addition to built-in Agno toolkits, implement custom Python functions and register them as agent-callable tools.

These functions are important because they demonstrate that the agent can do more than retrieve information.

### Tool A: Historical Return Calculator

Calculate historical price returns over a selected period.

Formula:

Return (%) = ((Ending Price - Starting Price) / Starting Price) × 100

The result must state the period used and clarify that historical returns do not predict future performance.

### Tool B: Moving Average Calculator

Calculate simple moving averages, such as the 20-day and 50-day SMA, when sufficient price history is available.

Formula:

SMA(n) = Sum of the latest n closing prices / n

These indicators help describe historical price trends but do not guarantee future direction.

### Tool C: RSI Calculator

Calculate the Relative Strength Index using a documented method, preferably the conventional 14-period Wilder calculation.

Formula:

RSI = 100 - (100 / (1 + RS))

Where RS is the ratio of average gains to average losses over the selected period.

The application should handle insufficient history and periods with zero average losses safely.

### Tool D: Affordability Calculator

Calculate the number of whole shares affordable within the user's budget.

Formula:

Affordable Shares = Floor(Available Budget / Share Price)

The calculator should also report the amount remaining after purchasing those shares.

For a diversified basket, it should calculate quantities separately for each allocation while respecting the total budget.

Brokerage, taxes, exchange charges, and other transaction costs are excluded unless explicitly modeled. This limitation must be shown to the user.

### Tool E: Stock Comparison Calculator

Compare selected stocks using available metrics, such as:

- Historical returns.
- Volatility.
- Moving averages.
- RSI.
- Valuation metrics, when comparable data is available.
- Market capitalization.
- Available financial information.

Missing metrics must be marked unavailable rather than silently treated as zero.

### Tool F: Risk and Volatility Calculator

Calculate historical volatility from daily returns, using a documented lookback period and annualization convention.

Formula for sample daily volatility:

Daily Volatility = Standard Deviation of Daily Returns

Annualized Volatility = Daily Volatility × Square Root of 252

The application should explain that volatility measures historical price variability and is not a complete measure of investment risk.

# 7. Agent Architecture

The initial implementation should use one primary Agno agent with multiple tools, rather than introducing multiple specialized agents immediately.

## Agent Responsibilities

- Interpret the user's requested analysis.
- Decide which registered tools are necessary.
- Retrieve relevant financial information.
- Invoke appropriate calculations.
- Summarize the retrieved evidence.
- Explain the screening results and risks.
- Return structured output suitable for Streamlit.

## Proposed Tool Registration

Register the following categories of tools:

1. Agno `YFinanceTools`.
2. Agno `DuckDuckGoTools`.
3. Custom historical-return calculator.
4. Custom moving-average calculator.
5. Custom RSI calculator.
6. Custom affordability calculator.
7. Custom volatility calculator.
8. Custom stock-comparison calculator.

The precise constructors, import paths, tool methods, and supported execution metadata must be verified against the installed Agno version during implementation.

The custom calculators should use deterministic Python logic. The LLM should interpret their results, not invent the numerical calculations.

## Suggested Processing Architecture

User Interface → Input Validation → Agno Agent → Registered Tools → Data Validation and Python Calculations → Stock Ranking and Explanation → Streamlit Results Dashboard

The architecture should keep financial calculations separate from UI code and agent instructions.

# 8. Stock Ranking Methodology

The application needs a transparent screening method so that its results are explainable and testable.

## Proposed Approach

Use a documented, configurable scoring system that combines relevant metrics, such as:

- Historical performance.
- Historical volatility.
- Trend indicators.
- Available financial fundamentals.
- Relevant news and risk factors.
- Compatibility with the selected stock preference.

The precise weights should be defined and documented before the ranking feature is implemented.

### Important Rules

- Risk tolerance changes the screening criteria; it does not guarantee suitability.
- Historical returns should not be used alone to rank investments.
- A high RSI, low RSI, or positive moving-average trend is not an automatic buy signal.
- News sentiment must not override contradictory financial evidence.
- Missing data must not be silently assigned favorable scores.
- The application must explain why candidates were included and what could make them unsuitable.
- If the data is insufficient to rank candidates reliably, the application should return a clear limitation instead of manufacturing a ranking.

A score must be labeled as an application-generated screening score, not a probability of profit or a guaranteed expected return.

# 10. Error Handling and Data Quality

The application must remain usable when individual tools fail.

## Required Cases

**Yahoo Finance failure:** Show a clear message and avoid fabricating prices.

**Web search failure:** Continue the financial analysis if sufficient market data exists, while indicating that news analysis was unavailable.

**Insufficient historical data:** Mark the relevant metric unavailable.

**Invalid budget:** Ask the user to correct the input.

**Unsupported stock symbol:** Explain that the symbol could not be resolved or analyzed.

**Model API failure:** Show a recoverable error and allow the user to retry.

**Rate limits:** Handle the error gracefully and avoid uncontrolled repeated requests.

**Partial analysis:** Clearly identify which results are incomplete.

**Stale data:** Show the last available data date and warn when the data is older than the application's configured freshness threshold.

**Contradictory information:** Prefer source-specific facts and explain material discrepancies rather than combining them into an unsupported conclusion.

The application must never silently replace failed live retrieval with invented data.

# 11. Security and Privacy

- Store API keys in environment variables or Streamlit secrets.
- Never hardcode or expose API keys in source code or the interface.
- Do not display secrets in tool logs.
- Validate all user inputs.
- Avoid executing arbitrary user-supplied Python code.
- Keep database operations parameterized.
- Store only the information needed for watchlists and analysis history.
- Make it clear that the initial application uses local persistence and is not a multi-user financial platform.

# 12. Financial Disclaimer and Responsible Output

StockPilot AI is an educational stock-analysis and investment decision-support application.

It must display a visible disclaimer similar to the following:

"StockPilot AI provides AI-generated analysis based on available financial data and historical information. It is intended for informational and educational purposes and is not personalized investment advice. Stock prices and data may be delayed, incomplete, or inaccurate. Historical performance does not guarantee future results, and returns are not guaranteed. Investments in securities are subject to market risks, including the possible loss of capital. Users should independently verify information and consider their financial circumstances before making investment decisions."

The application must not:

- Guarantee profits or returns.
- Claim certainty about future stock prices.
- Present historical performance as a forecast.
- Claim to know a user's complete financial situation from a few form inputs.
- Treat a screening score as a guarantee of suitability.
- Present simulated results as actual investment performance.

Any future feature that offers individualized investment recommendations should receive an appropriate legal and regulatory review before public deployment.

# 14. Non-Functional Requirements

**Usability:** A first-time user should be able to complete an analysis without technical knowledge.

**Maintainability:** Separate the Streamlit interface, agent setup, tools, financial calculations, and persistence into distinct modules.

**Reliability:** A failure in one optional tool should not unnecessarily crash the entire application.

**Transparency:** Important metrics should be traceable to retrieved data or documented calculations.

**Performance:** Cache appropriate data and avoid unnecessary API calls. The application should communicate progress when a multi-tool analysis takes time.

**Extensibility:** The tool registry and stock universe should support future additions without requiring a complete rewrite.

**Reproducibility:** Save the analysis parameters, data dates, and scoring configuration needed to understand a previous result.

# 19. Risks and Dependencies

**Model and API compatibility:** The selected Groq-hosted GPT-OSS model must support the required tool-calling workflow.

**Agno API changes:** Tool constructors and execution metadata may vary across framework versions. Pin compatible dependencies and verify the installed APIs.

**Yahoo Finance limitations:** Data availability, freshness, rate limits, and financial coverage may vary. Yahoo Finance should not be treated as a guaranteed real-time or institutionally licensed data feed.

**Web search reliability:** Search results may be outdated, incomplete, or speculative. The application must retain source links and dates where available.

**Ranking quality:** A screening score can create a misleading impression of precision. Document the scoring method and avoid presenting it as a prediction of profit.

**Operational cost and latency:** Multiple tool calls can increase response time and API usage. Cache suitable data and use only the calls necessary for each analysis.

**Regulatory considerations:** Public deployment of individualized investment recommendations may create additional obligations. Review the applicable requirements before expanding the product's scope.

# 20. Final Product Definition

StockPilot AI will be a medium-level, AI-agent-based financial analysis application for Indian stocks.

Its distinguishing feature will not simply be that it generates investment-related text. It will combine actual tool execution, financial data retrieval, deterministic Python calculations, relevant web information, transparent stock screening, and an attractive interactive dashboard.

The initial product will use one Agno agent, the Groq API with GPT-OSS 120B, Yahoo Finance tools, DuckDuckGo search tools, custom financial-analysis functions, and Streamlit.

The user will provide a budget and investment preferences. The application will analyze available evidence, return a shortlist of stock candidates, explain the rationale and risks, calculate affordability, and show which tools were actually used.

**The guiding principle for development is simple: build a reliable, transparent, tool-using stock-analysis agent first, then build the polished dashboard around it.**
